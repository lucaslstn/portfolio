TP6 : Analyse des Flux DNS, ARP et HTTP

Auteur : Lucas Lestiennes Module : TC1

1. Émission d'une Requête DNS

Lorsqu'un utilisateur saisit une URL (ex: www.ozenne.com) sur son poste (PC0), le système doit d'abord obtenir l'adresse IP correspondante.

  1. Le poste vérifie sa table ARP pour obtenir l'adresse MAC de sa passerelle par défaut.
  2. La requête DNS est encapsulée et envoyée vers le serveur DNS via les différents routeurs du réseau.

2. Échange ARP Intermédiaire

Au cours du routage, si un routeur (ex: Routeur2) connaît l'IP de destination (le serveur DNS) mais pas son adresse MAC, il met la requête DNS en attente et émet une requête ARP.

  • ARP Request : "Qui possède l'IP 192.168.2.202 ? Répondez à [MAC_Routeur]".
  • ARP Reply : Le serveur DNS répond avec son adresse MAC.

Une fois la table ARP à jour, le routeur peut transmettre la requête DNS au serveur.

3. Résolution DNS et Réponse

Le serveur DNS traite la demande et renvoie une réponse contenant l'adresse IP associée au nom de domaine. Le PC0 reçoit cette information et peut désormais initier la communication réelle.

4. Requête HTTP

Maintenant que PC0 connaît l'IP du serveur web (ex: 192.168.1.254), il émet une requête HTTP (GET) pour récupérer la page d'accueil du site.
