TP4 : Services Réseau (DNS, HTTP, DHCP)

Auteur : Lucas Lestiennes Module : TC1

Tâche 1 : Configuration des Services Serveur

Étape 1 : Service DNS (Domain Name System)

Objectif : Rendre le serveur SERVEUR-DIDESC accessible via un nom de domaine plutôt que par son IP. Mise en place :

  1. Activation du service DNS sur le serveur.
  2. Création de l'enregistrement associant le nom de domaine à l'adresse IP du serveur.
  3. Configuration des clients (postes de travail) pour utiliser l'adresse IP de ce serveur DNS. Validation : Un ping vers le nom de domaine répond correctement, prouvant la résolution de nom.

Étape 2 : Services HTTP et DHCP

Nous ajoutons un nouveau serveur nommé MICANI pour héberger un site web et gérer l'adressage IP dynamique.

Service DNS (Rappel)

Le DNS joue le rôle d'annuaire. Pour le site www.ozenne.com, le serveur DNS DIDESC renvoie l'IP du serveur web MICANI. Sans cela, l'utilisateur devrait retenir l'IP du serveur web.

Service HTTP (Web)

Ce service héberge les fichiers du site internet (HTML/CSS). Lorsqu'un client demande www.ozenne.com, le service HTTP du serveur MICANI envoie les pages web à afficher.

Service DHCP (Dynamic Host Configuration Protocol)

Rôle : Automatiser la configuration IP des clients. Configuration :

  • Définition d'une plage d'adresses (pool).
  • Définition de la passerelle par défaut et du serveur DNS à fournir.
  • Activation du service. Résultat : Les postes de l'atelier récupèrent automatiquement une adresse IP valide dès leur connexion au réseau, sans configuration manuelle.

Tâche 2 : Interconnexion des Routeurs

Ajout d'interfaces Séries

L'ajout de cartes d'interface série sur ROUT-CLI et ROUT-SERV-B permet de relier physiquement les réseaux distants via une liaison WAN dédiée. Si la connexion ne fonctionne pas immédiatement, cela indique souvent un problème de configuration d'interface (activation "no shutdown") ou de protocole de routage manquant.
