2. Analyse des Flux

2.1 Requête DNS (Atelier-2 vers Serveur)

L'utilisateur tente de joindre www.ozenne.com. Le paquet DNS est généré à la couche Application (port 53).

Au niveau des équipements :

  • Hub : Diffuse la trame sur tous ses ports sans modification.
  • Switch : Transmet la trame vers le routeur en fonction de sa table MAC.
  • Routeur CLI : Reçoit la trame sur son interface LAN. Il modifie l'entête de la couche 2 (Liaison) : l'adresse MAC source devient celle de son interface WAN et l'adresse MAC destination devient celle de l'interface WAN du routeur suivant (ROUT-SERV).
  • Routeur SRV : Procède de même pour acheminer le paquet vers le serveur final. L'adresse MAC destination finale est celle du serveur DIDESC.

2.2 Requête HTTP

Une fois l'IP obtenue via le DNS, le client émet une requête HTTP (port 80).

3. Le Protocole ARP (Address Resolution Protocol)

Si une table ARP est vide, le système émet une requête ARP en broadcast (FFFF.FFFF.FFFF). Tous les équipements du segment reçoivent la demande, mais seul celui possédant l'IP recherchée répondra.

Points clés :

  • Les routeurs sont les seuls équipements à modifier les adresses MAC (Couche 2) lors du passage d'un réseau à un autre.
  • Les adresses IP (Couche 3) restent inchangées de bout en bout.
  • Une fois le réseau "cartographié" par l'ARP, les échanges suivants sont plus rapides car les adresses MAC sont mises en cache.
