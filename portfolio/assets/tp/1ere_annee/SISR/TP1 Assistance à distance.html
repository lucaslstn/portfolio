TP1 : Assistance à Distance

Auteur : Lucas Lestiennes
Module : SISR

Introduction aux avantages de l'assistance à distance

L'utilisation d'outils de prise en main à distance présente plusieurs atouts majeurs pour la gestion de parc informatique :

  • Accessibilité permanente : Ces solutions permettent d'accéder à un poste de travail à tout moment et depuis n'importe quel endroit, sous réserve de disposer d'une connexion internet et des outils adéquats. Les seules limites sont la dépendance au réseau et l'état physique de la machine (une panne matérielle empêchant tout accès).

  • Optimisation du temps : Pour un technicien, l'intervention à distance élimine les temps de trajet. Au lieu de se rendre physiquement chez le client ou sur le site concerné, il peut résoudre le problème directement depuis son bureau. C'est un gain d'efficacité considérable.

  • Économies financières : De ce fait, les coûts d'intervention sont réduits, car les frais de déplacement ne sont plus facturés au client ou à l'entreprise.

Solution 1 : Virtual Network Computing (VNC)

UltraVNC est une solution open-source populaire. Son fonctionnement repose sur une architecture client/serveur :

  • VNC Server : installé sur le poste à contrôler (celui qui a besoin d'assistance).
  • VNC Viewer : installé sur le poste du technicien (celui qui prend le contrôle).

L'installation nécessite de définir deux mots de passe : un pour le contrôle total et un autre pour le mode "vue seule" (view-only).

Configuration du Serveur VNC

VNC Server offre de nombreuses options pour affiner la sécurité et le comportement de la connexion :

Gestion de la déconnexion (When Last Client Disconnects)

Trois comportements sont possibles lorsque le technicien se déconnecte :

  • Do Nothing : La session reste active.
  • Lock Workstation : La session est verrouillée.
  • Logoff Workstation : La session est fermée.

Clavier et Souris (Keyboard & Mouse)

Permet de restreindre les actions du technicien :

  • Disable Viewers inputs : Le technicien ne peut que voir l'écran, sans interagir.
  • Disable Local inputs : Bloque la souris et le clavier de l'utilisateur distant pendant l'intervention.

Connexions Entrantes (Incoming connection)

Gère l'autorisation des connexions :

  • Display Query Windows : Demande une confirmation à l'utilisateur avant d'autoriser la prise en main.
  • Sharing indicator : Affiche un cadre coloré pour signaler que l'écran est partagé.

Connexions Multiples (Multi Viewer Connections)

Gère le comportement si plusieurs techniciens tentent de se connecter :

  • Disconnecting all existing connections : La nouvelle connexion éjecte les précédentes.
  • Keep existing connections : Permet le travail collaboratif.
  • Refuse new connections : Bloque toute nouvelle tentative si une session est déjà en cours.

Divers (Misc.)

  • Remove wallpaper : Supprime le fond d'écran pour accélérer l'affichage.
  • Enable Blank Monitor : Écran noir sur le poste distant pour la confidentialité.
  • RDPmode : Permet de se connecter à une session RDP existante plutôt qu'à la session console.

Solution 2 : TeamViewer

TeamViewer est une solution propriétaire très répandue, fonctionnant sur un système d'identification par ID unique. Elle est souvent jugée plus conviviale qu'UltraVNC.

Fonctionnement

Contrairement aux IP, TeamViewer attribue un ID fixe à la machine. L'utilisateur communique cet ID et le mot de passe temporaire au technicien.

L'outil permet deux modes principaux :

  1. Contrôle à distance : Prise en main complète.
  2. Transfert de fichiers : Échange de données uniquement.

Une fois connecté, une barre d'outils en haut de l'écran permet d'accéder à des fonctionnalités avancées comme le transfert de fichiers, l'envoi de commandes système (Ctrl+Alt+Suppr) ou le chat. L'utilisateur distant est notifié de la prise en main et peut y mettre fin à tout moment.

Solution 3 : Bureau à Distance Windows (RDP)

Le protocole RDP (Remote Desktop Protocol) est natif aux environnements Microsoft. Il est disponible sur Windows, mais aussi via des clients sur Android, iOS et macOS.

Mise en place

  1. Activer l'option "Bureau à distance" dans les paramètres système du poste cible.

  2. Sur le poste client, lancer l'application "Connexion Bureau à distance".

  3. Entrer le nom de la machine ou son adresse IP.

  4. S'authentifier avec les identifiants d'un compte utilisateur autorisé sur la machine distante.

Particularité du RDP : Contrairement à VNC ou TeamViewer qui partagent l'écran de la session console, le RDP ouvre une nouvelle session (ou capture la session existante en déconnectant l'utilisateur local). L'utilisateur devant l'écran physique ne voit pas ce que fait le technicien ; il est déconnecté. C'est idéal pour l'administration de serveurs.

Solution 4 : SSH (Secure Shell)

SSH est le standard pour l'administration sécurisée en ligne de commande, particulièrement sur les systèmes Linux (comme Debian 11 utilisé ici).

Outils

  • OpenSSH Server : Le service à installer sur la machine Debian (apt install openssh-server).
  • PuTTY : Un client SSH populaire pour Windows.

Configuration sur Debian

Après installation, il faut configurer le fichier /etc/ssh/sshd_config pour sécuriser l'accès, par exemple en limitant les utilisateurs autorisés avec AllowUsers user1. Un redémarrage du service est nécessaire : service sshd restart.

Utilisation de PuTTY

Sur le poste client, on lance PuTTY, on renseigne l'adresse IP du serveur et le port (22 par défaut).

Une fois connecté, on obtient un terminal distant permettant d'exécuter toutes les commandes système, de modifier des fichiers ou de gérer les mises à jour, avec l'avantage de pouvoir faire des copier-coller depuis le poste client.

Synthèse : Comparatif des Solutions

Solution Avantages Inconvénients
UltraVNC Gratuit, très configurable, léger. Interface austère, configuration initiale plus complexe, moins sécurisé par défaut.
TeamViewer Très simple (ID/MDP), traverse les pare-feux facilement, transfert de fichiers. Payant pour usage commercial, dépendance aux serveurs de l'éditeur.
RDP (Bureau à distance) Intégré à Windows, performant, gratuit. Déconnecte l'utilisateur local, nécessite une configuration réseau (redirection de ports) pour l'accès externe.
SSH Standard, très sécurisé, rapide, scriptable. Ligne de commande uniquement (CLI), nécessite des compétences système.
