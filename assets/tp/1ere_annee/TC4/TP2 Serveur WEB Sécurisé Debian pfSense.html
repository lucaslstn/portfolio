TP2 : Déploiement d'un Serveur Web Sécurisé (Debian 11 & pfSense)

Auteur : Lucas Lestiennes Module : TC4

1. Architecture du Réseau

Le projet consiste à mettre en place une infrastructure complète comprenant un pare-feu, des serveurs DNS et un serveur Web.

Schéma de principe :

  • LAN : Réseau interne (Administration).
  • DMZ : Zone Démilitarisée (Hébergement du serveur Web).
  • WAN : Accès vers l'extérieur.

Note importante : L'adresse IP du serveur DNS LAN est 192.168.0.53.

2. Configuration du Pare-feu pfSense

pfSense assure le routage et la sécurité entre nos trois zones (WAN, LAN, DMZ).

Installation et Interfaces

  1. Création de la VM (FreeBSD 64-bit).
  2. Configuration de 3 cartes réseau : Pont (WAN), Interne (LAN), Interne (DMZ).
  3. Affectation des interfaces via la console pfSense.

Administration Web

L'interface de gestion est accessible via http://192.168.0.1 depuis un poste du LAN.

  • WAN : Récupère son IP via DHCP (accès ponté).
  • LAN : 192.168.0.1/24.
  • DMZ : À activer et configurer (ex: 192.168.10.1/24).

3. Services DNS (Windows Server 2022)

Nous gérons deux serveurs DNS pour assurer la résolution interne et externe.

  1. Installation du rôle DNS sur Windows Server.
  2. Configuration des redirecteurs : Le DNS LAN pointe vers le DNS FAI, qui lui-même pointe vers les DNS racines ou ceux du lycée.
  3. Zones de recherche : Création d'une zone 148.sio (basée sur l'octet affecté).

4. Configuration du Serveur Web Debian 11

Le serveur Web est hébergé en DMZ sous Debian 11.

Préparation du Système

  • Configuration de l'IP statique dans /etc/network/interfaces.
  • Mise à jour du fichier sources.list pour pointer vers les dépôts officiels Debian Bullseye.
  • Exécution de apt update && apt upgrade.

Installation des Services

  1. Apache2 : apt install apache2.
  2. MariaDB : Installation du moteur de base de données et sécurisation via mysql_secure_installation. Création d'un utilisateur administrateur avec les privilèges SQL.

Virtual Hosts et Publication

Nous créons deux sites distincts.

  1. Création des répertoires dans /var/www/html/site1.
  2. Configuration des fichiers .conf dans /etc/apache2/sites-available/.
  3. Activation des sites avec a2ensite et redémarrage d'Apache.

5. Tests et Accès Extérieur

Test Local

L'accès à http://site1.148.sio depuis le LAN confirme que le DNS et Apache fonctionnent de concert.

Accès WAN (NAT/Port Forwarding)

Pour rendre le site accessible depuis l'extérieur, nous configurons une règle de NAT sur pfSense : rediriger le port 80 de l'interface WAN vers l'IP du serveur Debian en DMZ.
